# Архитектура и аудит качества

Актуально для версии 1.0.1. Аудит проведён 6 ноября 2026 года для сценария одного пользователя и сотен задач в одном браузере.

## Устройство приложения

```text
index.html
    │ события пользователя
    ▼
app.js ───────────────► DOM и диалоги
    │
    ├──► task-utils.mjs ─► нормализация, сроки, фильтры
    │
    └──► localStorage ───► task-list:v1
```

- `app.js` владеет состоянием текущего экрана и связывает его с DOM.
- `task-utils.mjs` содержит чистую бизнес-логику, которую можно запускать без браузера.
- `localStorage` — единственное постоянное хранилище. Приложение не отправляет задачи по сети.
- Полная перерисовка списка имеет линейную сложность `O(n)` и подходит для сотен задач.

## Решение по модульности

Дополнительное дробление `app.js` сейчас не оправдано: в приложении один экран, один источник состояния и нет повторно используемых представлений. Отделение хранилища, контроллеров и компонентов добавило бы больше связей, чем полезной логики.

Следующее разделение имеет смысл только при появлении второго экрана, серверной синхронизации или повторно используемых компонентов.

## Безопасность

- Пользовательский текст вставляется через `textContent`, поэтому HTML и скрипты из названия задачи не выполняются.
- Записи из `localStorage` проходят проверку типов, длины и календарных значений.
- При нормализации сохраняются только известные поля задачи.
- В репозитории нет ключей, токенов и серверных секретов.
- GitHub Actions получает только право чтения содержимого репозитория.

`localStorage` не является зашифрованным хранилищем. В задачах не следует хранить пароли, платёжные данные или другую чувствительную информацию.

## Что показал аудит

Исправлено:

- задача без указанного времени теперь остаётся активной до конца выбранного дня;
- невозможные календарные даты больше не попадают в состояние приложения;
- посторонние поля удаляются при чтении данных;
- ключевая логика сроков и нормализации покрыта модульными тестами;
- каждый push и pull request проверяется в GitHub Actions.

Осознанные ограничения:

- данные доступны только в текущем браузере;
- несколько вкладок не синхронизируют изменения в реальном времени;
- список полностью перерисовывается после изменения.

Для текущей нагрузки эти ограничения приемлемы. Серверное API нужно добавлять при синхронизации между устройствами, а частичную отрисовку — когда список вырастет до тысяч элементов.
